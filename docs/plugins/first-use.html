安装后完成第一个动作

已测试宿主 DSH 0.2.2-rc.1。先确认 Node.js 24.9+ 与可运行的 dsh web。模型凭据仅在 Host 配置。

准备与切换

只安装你需要的插件。Slack UI 与 Channels 切换时，先移除另一个：

dsh plugin --profile web remove dsh-slack
dsh plugin --profile web remove dsh-channels

上述两行是按需移除命令，不要求每次都执行。随后运行所选插件的安装命令，再重启 dsh web。

若最小 Linux 环境提示无法创建默认工作区：Native DSH → Preview Continue → Choose workspace → Edit path → 输入现有目录的绝对路径 → Enter → Open。

Sidebar History

dsh plugin --profile web add dsh-sidebar-history@0.2.3
dsh web
  1. 在历史侧栏打开任务卡片，查看最新回复与真实 TODO 完成数。
  2. 若需验证模型链路，在 Host 配好凭据后发送一个明确任务，等待真实回复。
  3. 刷新页面，确认同一会话的已保存回复与进度可再次打开。

遥测默认关闭。测试事件不代表真实用户量；未单独证明与其他布局插件的组合兼容性。

DSH Slack UI

dsh plugin --profile web add 'git+https://github.com/liush2yuxjtu/dsh-slack.git#289612132d17e87acc761c5c336eee1af0f5cf45'
dsh web
  1. 打开 Chats，在列表底部输入框发送一个新任务，确认新建独立 Session。
  2. 选中该任务，在右侧 Thread 输入框续聊，确认保留上下文。
  3. 刷新后重新选择任务，确认历史和 TODO 可恢复；Native DSH 可返回设置。

不连接 Slack 服务；与 Channels 二选一。每条根消息创建新 Session，Thread 回复继续当前 Session。

DSH Channels

dsh plugin --profile web add 'git+https://github.com/liush2yuxjtu/dsh-channels.git#a6662dafc209e7ae7d39d35dc24a59515acfd797'
dsh web
  1. 打开 Channels，先发送普通消息，确认只保存人类讨论。
  2. 发送 @deepseek 加具体任务，确认创建 Mission Thread 与独立 Session。
  3. 在该 Thread 再次 @deepseek 续办；普通回复只留团队备注。
  4. 刷新并重开任务，检查历史、回复和 TODO。只邀请可信 Host 使用者。

可信 Host 的 Alpha。频道邀请不隔离 Host owner 的其他会话权限；普通 Thread 回复不调用模型。

DSH Artifacts

dsh plugin --profile web add 'git+https://github.com/liush2yuxjtu/dsh-artifacts-extension.git#9826d31d7838a468e54881d11e4f5f3970d29c29'
dsh web
  1. 已有 artifact-store 配置和缓存时，打开 Artifacts，按标题或标签搜索已有成果。
  2. 选中成果，检查 HTML 交互预览；需要 localStorage 时新标签打开。
  3. 复制文件路径，外部更新后点击 Refresh。
  4. 如果尚无 store，按仓库 README 配置既有 artifact-store skill；仅安装此包不会自动提供三个创作 skills。

当前0.1.3需要已配置的 artifact-store 和本地缓存。创建、存储、Tweaks 的三个外部 skills 未随包交付；多类型编辑器尚未发布。
