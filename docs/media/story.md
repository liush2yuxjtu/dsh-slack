# Feature recording story

Source instructions: [my-release-skills](https://github.com/liush2yuxjtu/my-release-skills/tree/6c50908b990afd0e001dfc63afb4227a3f917c15), revision `6c50908b990afd0e001dfc63afb4227a3f917c15`.

The audience is a DSH user who handles more than one topic. The result is returning to one topic with its own conversation and TODOs intact.

## Sources opened on 2026-11-10

These are product documentation and usability observations. They do not establish conversion effects for this plugin.

| Source | Observation used in this recording |
| --- | --- |
| [Slack threads](https://slack.com/help/articles/115000769927-Use-threads-to-organize-discussions) | Selecting a Thread opens that discussion for a reply. |
| [Slack thread examples](https://slack.com/resources/using-slack/tips-on-how-best-to-use-threaded-messages) | A short entry can retain the detailed discussion in its Thread. |

| [Notion page opening](https://www.notion.com/help/views-filters-and-sorts) | Side peek retains an interactive list beside the selected detail. |
| [Wistia demo](https://wistia.com/demo) | The demonstration presents a recognizable task before describing its controls. |
| [NN/g video usability](https://www.nngroup.com/articles/video-usability/) | Start with useful content. Keep a text explanation and representative still beside the video. |
| [NN/g animation usability](https://www.nngroup.com/articles/animation-usability/) | A visible, deliberate transition is easier to follow than an unexplained state replacement. |
| [NN/g motion purpose](https://www.nngroup.com/articles/animation-purpose-ux/) | Motion should show feedback or a state change. Decorative movement adds no proof. |

No third-party footage is used. Stock selection and portrait cutout do not apply to this browser recording.

## Shot plan

| Beat | Real operation | Framing | Hold |
| --- | --- | --- | --- |
| New topics | Send two ordinary planning requests in Chats. Each creates a separate session. | Full application in the complete recording. | Keep actual model waits. |
| Continue | Reply in the launch Thread to mark screenshots complete. | List and native Thread. | Wait for actual API completion. |
| Short clip context | Show the completed workshop Thread beside the launch entry. | Crop to the list and Thread, retaining the product header. | About 1 second. |
| Open Thread | Move the pointer to the launch entry and click. Expand its native TODO list. | Same fixed crop. | Keep each operation visible. |
| Result | Hold the launch title, its reply and 2/3 TODO state. | Same fixed crop. | At least 3 continuous seconds. |

The eight-second MP4 and GIF use the same continuous interval from the immutable full recording. The short clip demonstrates reopening an existing Thread. The full recording includes creating both sessions and actual DeepSeek processing.

## Execution boundaries

The recording runs on the current GPT Work Linux machine, following the installed Work execution mapping. It uses the public repository build rather than a claimed production Release. No PR or Release is created. English and Chinese assets use their respective native UI and message language. This language choice serves the two README versions. There are no generated replies, seeded TODO events, explanatory overlays, speed changes, music or external messages.
